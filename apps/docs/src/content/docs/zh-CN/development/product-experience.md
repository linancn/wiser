## 这份文档约束什么

本指南约束 `apps/web` 中用户能够看到和操作的产品表面。视觉 Token、字体、主题和组件语义见 [WISER Design System](/architecture/design-system/)；路由、Server Component、数据访问和 Playwright 流程见[前端开发](/development/frontend/)。

产品界面不是开发文档、架构图或运行手册。它首先帮助使用者回答：

1. 我现在位于平台的哪一层？
2. 我能完成什么任务？
3. 当前状态对我的工作有什么影响？
4. 下一步可以做什么？

实现原理、内部服务、配置项和排障步骤进入文档、日志或受控运维工具，不进入普通业务页面。

## 固定的信息层级

所有系统使用同一条层级，不得混排：

```text
WISER Portal
  → 业务系统
    → 系统工作区
      → 领域对象与对象内页签
```

| 层级       | 作用                                          | 当前示例                               |
| ---------- | --------------------------------------------- | -------------------------------------- |
| Portal     | 说明 WISER 是什么、有哪些系统，并引导统一登录 | `/zh-CN`、`/en`                        |
| 业务系统   | 在平级业务边界之间切换                        | 数据基座、智能体演练场                 |
| 系统工作区 | 完成该系统内的稳定任务                        | 数据目录、数据接入；演练场景、演练运行 |
| 领域对象   | 查看或操作一个具体 DataItem、场景、Run 或任务 | Run 总览 / 协作 / 评测 / 追踪 / 回放   |

约束如下：

- WISER Logo 永远返回当前语言的 Portal；Portal 不是第三个业务系统。
- 一级系统导航固定把基础能力“数据基座”放在“智能体演练场”之前。
- Portal 和登录页不显示任何系统二级导航。
- 二级导航只在进入对应系统后显示；对象内页签不得提升为平台导航。
- 新系统只能加入一级系统列表，不能新建平行 Header、身份入口或主题控制。

## 产品命名

| 概念               | 中文产品名   | 英文产品名      | 说明                         |
| ------------------ | ------------ | --------------- | ---------------------------- |
| 平台               | WISER        | WISER           | 不翻译、不作为系统标签       |
| Data Foundation    | 数据基座     | Data Foundation | 一级业务系统，排在第一位     |
| Agent EXCON        | 智能体演练场 | Agent EXCON     | 中文界面不直接显示英文品牌名 |
| Scenario workspace | 演练场景     | Scenarios       | 智能体演练场二级任务         |
| Run workspace      | 演练运行     | Exercise runs   | 智能体演练场二级任务         |

协议名、代码标识符和产品展示名分开维护。URL、DTO、数据库字段可继续使用稳定英文标识；用户可见标题按上表表达。

## 公开入口与登录边界

- `/` 重定向到中文 Portal `/zh-CN`；`/en` 提供同构英文 Portal。
- Portal、登录页与 Auth transport 路由允许匿名访问。
- 使用 Supabase Auth 的环境中，进入数据基座或智能体演练场工作区前必须拥有已验证 Session；匿名请求保留目标地址并跳转到对应语言的登录页。
- `WISER_AUTH_MODE=off` 只用于显式本机参考预览，不能作为生产身份模式。
- Portal 允许匿名使用者理解两个系统的职责，但不展示项目数据、运行数据或伪造业务指标。
- 登录页只说明组织账户、组织范围和项目权限；Supabase、Cookie、Token、publishable key 等实现说明进入开发文档。

## 产品语言

### 写作顺序

一段界面文案按需要依次回答：用户目标 → 当前状态 → 影响 → 下一步。通常一到两句已经足够。

| 使用场景 | 应该写                                          | 不应该写                                     |
| -------- | ----------------------------------------------- | -------------------------------------------- |
| 页面导语 | 用户能在这里完成什么                            | 模块采用了哪些数据库、队列、投影或 DTO       |
| 空态     | 当前没有什么，以及用户现在能做什么              | “API 尚未提供”“不使用 fixture”“不会伪造数据” |
| 失败态   | 发生了什么、工作是否受影响、可执行的恢复动作    | HTTP 状态、环境变量、内部 URL、健康检查命令  |
| 权限态   | 当前账户不能访问，以及向谁申请                  | Role/Scope/Tenant 校验链路                   |
| 专业详情 | 完成任务确实需要的 Trace、Span、CRS、版本和哈希 | 与当前任务无关的基础设施细节                 |

普通产品页面禁止出现：

- 环境变量名、凭据名、内部主机名和内部 URL；
- HTTP 401/403/5xx、原始错误码或上游响应正文；
- DTO、DAL、Capability Registry、Worker、Outbox 等实现词；
- “参考样例没有补齐”“接口尚未覆盖”等开发过程叙事；
- 要求普通用户检查数据库、对象存储、日志或健康端点的恢复步骤。

如支持团队需要关联问题，只显示无敏感信息的支持编号；技术原因写入服务端日志。

## 状态组件合同

- 空态说明当前范围，并提供一个可执行动作；没有动作时说明何时或由谁补充。
- 失败态由简短标题、影响说明、恢复建议和主操作组成；`role="alert"` 只播报这些用户信息。
- 同一动作从按钮、进行中状态到完成提示保持同名。
- 状态同时使用文字与形状，不能只依赖颜色。
- 原始协议 code 只在专业详情按需显示，不与每个状态标签重复。
- 不得为了页面“看起来有数据”而把示例、缓存或推断值混入实时业务状态。

## 国际化与实现

- 所有可见文案进入 `apps/web/src/lib/i18n.ts` 的同构字典；组件内不得散落 `locale === ...` 的双语文案分支。
- 中文先按自然、专业的人类表达完成，再写语义等价的英文；英文不能多出或缺少事实、状态或操作。
- 第三方控件的可访问名称也必须由字典显式提供，不能依赖浏览器或库的默认语言。
- 导航顺序和路径判断集中在纯配置/函数中；页面组件不得用“不是数据基座就当作演练场”一类隐式分支。
- 失败原因可以在服务端分类，但浏览器只接收安全的产品文案和必要的支持编号。

## 新系统接入清单

1. 在一级系统配置中加入唯一 ID、稳定入口和双语产品名，并说明其与既有系统平级的业务职责。
2. 复用 Portal、Header、统一登录、主题、语言和 Footer，不创建第二套平台外壳。
3. 为系统定义少量、任务导向的二级工作区；对象内页签留在对象页面。
4. 同时补齐中文和英文 Portal 说明、导航、页面、空态、失败态与权限态。
5. 确认匿名只能看到适合公开的系统介绍；项目内容经过统一 Session 和系统授权。
6. 增加纯导航测试和 Playwright：Portal、两种语言、两种主题、桌面、390px、键盘、reduced motion、登录 continuation 与技术信息不泄露。

## 验收

每项产品界面改动至少验证：

- Portal → 系统 → 工作区 → 对象层级清楚，且没有重复或倒置导航；
- 中文没有未约定的英文产品名，英文没有遗漏的中文叙述；
- 页面首屏不包含环境变量、内部 URL、HTTP 状态或开发恢复步骤；
- 深浅色、桌面与 390px 无横向溢出，主操作无需 hover；
- Skip link、一级/二级导航、主题、语言和主操作可由键盘到达；
- reduced motion 下没有必要之外的动画；
- 普通失败态不泄露服务器秘密或原始响应。
